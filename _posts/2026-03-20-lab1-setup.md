## Problem Statement 
LAN rely on Layer 2 protocols - **ARP**and **MAC Switching** that were designed for efficiency, not security. This lab investigated how an attacker already present on a network segment can exploit these weaknesses to intercept traffic bewteen other hosts without ever breaking an encryption or authentication mechanism at higher layers.

### Approach
The lab was structured as a progressive attack chain:

1. **Initial Access & Network Discovery** — Gained a foothold on the network and identified live hosts using `ip a show eth1` and `nmap`.
2. **Passive Sniffing** — Used Wireshark to observe traffic on the network segment without any active interference, confirming that ICMP packets were being exchanged between Alice and Bob.
3. **MAC Flooding** — Flooded the switch's MAC address table to force it into hub-mode, causing it to broadcast all frames to every port, enabling promiscuous capture.
4. **ARP Spoofing / MITM** — Launched an ARP spoofing attack using Ettercap to position the attacker machine between Alice and Bob, intercepting HTTP traffic and capturing credentials.
5. **Traffic Manipulation** — Went beyond passive interception to actively manipulate traffic in transit, achieving full man-in-the-middle control.

### Tools Used
1. **Nmap** - for network host and Discovery
2. **ifconfig** - interface and IP enumeration
3. **Wireshark** - passive packet capture and traffic analysis
4. **Ettercap** - arp spoofing and MITM attack execution
5. **curl** - HTTP request crafting with captured credentials

### Lessons Learnt

- **MAC flooding degrades switch security** by forcing broadcast mode, eliminating the isolation that VLANs and switching normally provide.
- **ARP has no authentication** — any device can send a gratuitous ARP reply claiming to own any IP, making spoofing trivially easy on unprotected networks.
- **Plaintext protocols are critically dangerous** when a MITM position is achieved; HTTP credentials are exposed in full.
- **ARP packet validation (Dynamic ARP Inspection)** is an effective countermeasure — Ettercap's MITM attempt failed against hosts with ARP validation enabled.
- **Ettercap's graceful teardown** (RE-ARPing) demonstrates that sophisticated tools clean up after themselves, making forensic detection harder.
- Active traffic manipulation goes beyond credential theft — a MITM attacker can modify data in transit in real time.
